# Najd 1.1.7: source-owned indexes and observable harvesting

The selected source owns its actual season and episode numbering. TMDB supplies display metadata and an independently identified canonical work; its season split is not imposed on a source edition. Source metadata and canonical matching remain separate. Missing source release year does not prevent independently indexing that source, and is never filled with an upload date or copied from TMDB as observed evidence.

Each provider plus original series reference receives a stable `source:<provider>:<SHA256-prefix>` work key. Every dubbed series reference remains separate, even from another dubbed reference on the same site. Neither runtime similarity, matching title, year nor IMDb ID silently merges dubbed cuts. Existing canonical playback APIs remain compatible; the new client selects a source edition before presenting its actual episode index.

Observed fixtures exercise the original Valley of the Wolves as 55+42 in 3isk and 1–97 in 3cktv, separately from Pusu's 93-link subtitled source. The dubbed fifth part's missing episode36 is reported as a gap; no episode is generated to fill it. Diagnostics may shorten long summaries explicitly; persisted episode rows and source pagination remain complete and resumable.

The verified 3cktv redirect reaches e.3cktv.cam. Its actual GET search form, nested duplicate cards, eplist episode grid and observed `do=watch` button are parsed by code. The broken desktop-only redirect is avoided by using the existing common HTTP client profile. All HTTPS, explicit domain, DNS/redirect safety, time, body and concurrency guards remain active. Six first/middle/last samples of the original and subtitled Pusu returned direct HLS and passed bounded playlist checks. A playlist or container-prefix check is not full decoding or physical-device certification. The other 3isk samples returned an entry page, not a direct media stream; no gate is bypassed or reported as successful playback.

Opening a work card now queues a bounded, deduplicated harvest and returns metadata immediately. Source favorites previously ignored by the TMDB-only trigger are queued using their original source reference. The SQL migration preserves owner/link checks, private RLS, retries, leases, hourly refresh, account identifiers and media expiry. Existing real source favorites are backfilled; no synthetic users or source episode lists are introduced. Failed cloud startup is retried without deleting the saved owner, session or local favorites.

The Arabic administration page separates actual aggregate totals from the last100 sampled rows, source indexing from media probing, and client player errors from source/network errors. `/api/v1/admin/report` requires the admin bearer key and exports an allowlisted support report. Credentials, cookies, raw pages, signed media links and personal identifiers are excluded. The actual client version/build and safe playback error codes are recorded without raw native error strings or media URLs. Reports remain for the owner to download and share; they are not automatically sent to AI or email.

The client update is required for source-edition selection, bounded status feedback and device error reporting. The server and database changes also repair background source favorites for existing installations. Release artifacts and the authenticated Web bundle must pass the common source verification workflow before delivery.
