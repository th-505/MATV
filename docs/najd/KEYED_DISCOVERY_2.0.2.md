# المطالبة المباشرة بمفاتيح المهام — قيد التحقق الحي

المهام الحديثة معروفة المفاتيح عند طلب العمل وبعد حفظ دفعة بحث المزودين. المطالبة بها عبر المفتاح الأساسي تتجنب مسح طابور الحلقات القديم. تبقى المهمة والحالة والمحاولات وقفل 90 ثانية في Supabase؛ الإشعارات في الذاكرة تسريع اختياري وليست مخزن المهام. إعادة التشغيل تعود للمطالبة الدائمة الموجودة.

- حفظ دفعة ناجح يرسل مفاتيحها إلى العامل؛ فشل الحفظ لا يعلنها.
- حدود 20 بحثًا و4 فهارس وفيديوين ثابتة، والمطالبة عبر المفاتيح تستعمل الأقفال نفسها.
- الطلب الصريح للعمل أو الحلقة يوقظ مفتاحه حتى إذا كان مسجلًا سابقًا.
- الإشعارات محدودة بألف مفتاح لكل مسار، دون نصوص بحث أو روابط فيديو أو أسرار.
- غياب RPC الجديد يرجع إلى مسارات المطالبة الموجودة، دون تعطيلها أو تخفيضها إلى عامل المهمتين القديم.
- RPC مخصص لـservice_role فقط؛ لا صلاحية لـanon/authenticated، وsearch_path فارغ.

## عائق النشر

فشلت أدوات Supabase في إنشاء الوظيفة بسبب مهلة إنشاء اتصال، بما فيها محاولة execute_sql؛ لم يتحقق تشغيل الوظيفة أو صلاحياتها على الإنتاج. لا يُدمج هذا التغيير قبل تطبيق الترحيل والتحقق الحي بمعاملة متراجعة تطالب بـ20 مهمة معروفة وتراجعها. فهرس الطابور الكبير السابق ليس شرطًا لهذا المسار، وتبقى معالجته منفصلة.

اختبار الإنتاج المعد مسبقًا: `scripts/verify_keyed_discovery_claims.sql`. ينشئ 21 مهمة داخل معاملة، ويتحقق من سقف 20 ومن رفض المسار الخطأ ومن صلاحيات الخدمة، ثم يتراجع عن كل الكتابات.
