# المرحلة الأولى: عزل أكوام وإثبات مفهوم قصة عشق

تاريخ الفحص: 2026-10-12 UTC. المستودع: `theeb505/Al-Qahtani`، أساس العمل: `0cfdc5c`.

تحديث لاحق: أكد المستخدم تشغيل الرابط نفسه على Safari في آيفون عبر 4G مع الصوت والتقديم والتأخير، دون ترويسات مخصصة أو 403. اعتمد دمج المرحلة الثانية التشغيل المباشر بناءً على هذه التجربة. النتائج أدناه سجل للفحص الأول قبل شهادة المستخدم؛ حالة الدمج الحالية وحدود اختبار Flutter والتخزين موثقة في [تقرير المرحلة الثانية](PHASE2_3ISK_INTEGRATION.md).

## النتيجة

نجح استخراج رابط HLS للحلقة المطلوبة، ثم تحميل المانيفست والجودة والمقاطع وتشغيل الفيديو في Chromium عبر HLS.js. لا يحتاج مسار الويب المختبر إلى بروكسي لترويسات البث أو تضمين المشغل. لا يزال قرار تمرير الرابط مباشرة من السيرفر إلى هاتف المستخدم مشروطًا بفحص شبكة ثانية وجهاز Flutter حقيقي؛ لم يُنفّذ هذان الفحصان في البيئة المتاحة.

## التغييرات وحماية العقود

- نُقل محتوى `server/basri-source.mjs` كاملًا إلى `server/providers/akoam.mjs` دون أي تغيير في المنطق أو التصديرات أو مفاتيح JSON.
- يستورد `server/app.mjs` المزود مباشرة، ويعيد `basri-source.mjs` تصدير الواجهة نفسها لحماية السكريبتات والاستيرادات السابقة.
- ملفات `match-playback.mjs` و`match-production.mjs` و`news-runtime.mjs` مطابقة للأصل بايتًا ببايت. لم تتغير ملفات Flutter أو التخزين أو المكتبة.
- `server/test-poc-3isk.mjs` مستقل ولا يضيف مزود قصة عشق إلى واجهات الإنتاج.
- `package.json` موجود في الجذر. نُفّذ `npm install` من `server/` بنجاح، ويستخدم npm الحزمة في الجذر. لا توجد تبعيات تشغيل إضافية؛ `fetch` مدمج في Node >=22.

## المسار الذي يعمل فعليًا

الطلب المباشر إلى `/see/` دون جلسة أعاد HTTP 302 إلى صفحة تفاصيل الحلقة، ثم HTTP 200 دون رابط التضمين المطلوب. لذلك يبدأ السكريبت بزيارة صفحة الحلقة، ثم يرسل كوكي الجلسة وReferer إلى صفحة المشاهدة. لا تُرسل كوكي المصدر إلى ukrcdn.

ظهر التضمين `https://3iskk.xyz/embed/1/266404/2/`، ومنه `https://ukrcdn.club/e/39ce6836-fc1a-4250-9269-55c982a6553b`.

صفحة ukrcdn الحالية لا تحتوي رابط `.m3u8` نصيًا. تحتوي طلب `fetch` إلى `/api/videos/<id>/playback?g=...` على نفس النطاق؛ يستخرج السكريبت الرابط من النص باستخدام JSON.parse دون تنفيذ JavaScript المصدر، ويقرأ حقل `url` من JSON. لا يسمح بمسار playback API على نطاق آخر. يبقى استخراج الرابط النصي المباشر مدعومًا.

الرابط الناتج وقت الفحص كان على `s4.ukrcdn.xyz`؛ ظهر `s9.ukrcdn.xyz` في تجربة سابقة. يحمل الرابط `token` و`expires`، ولذلك لم تُحفظ قيمة التوكن في التقرير أو ملفات الأدلة. نجاح الاستخراج وحده لا يثبت التشغيل أو صلاحية الرابط من شبكة أخرى.

| IP-Binding من شبكة ثانية | لم يُنفّذ | المتصفح وNode يستخدمان منفذ خروج البيئة نفسه؛ لا يُعدان شبكتين مختلفتين |

| Embed داخل موقع التطبيق | لم يُختبر | نجح HLS المباشر؛ لم تُحسم سياسات تضمين ukrcdn |

جميع طلبات الإنترنت استخدمت بروكسي الخروج الخاص بالبيئة السحابية. المتصفح طلب عناوين CDN مباشرة، دون بروكسي تطبيقي لحقن الترويسات، ودون تعطيل CORS أو التحقق من TLS. لا تستخدم الويب لتعيين Referer يدويًا؛ المتصفح يتحكم فيه. المقاطع بلا Origin لم تحمل ACAO، لكن مع Origin أعاد CDN الأصل المناسب. لذلك لا يُستنتج فشل CORS من طلب curl بلا Origin.

الأدلة المختصرة دون query tokens في [PHASE1_3ISK_EVIDENCE.json](PHASE1_3ISK_EVIDENCE.json).

## إعادة التشغيل

```sh
cd server
npm install
node test-poc-3isk.mjs
```

أو من جذر المستودع: `npm run poc:3isk`. في بيئة بروكسي مع Node 24 الداعم للخيار: `node --use-env-proxy server/test-poc-3isk.mjs` من الجذر. لا تستخدم هذا الخيار على إصدار لا يدعمه؛ استخدم إعداد شبكة ملائمًا للإصدار. أخطاء HTTP أو الاستخراج تنهي السكريبت برمز 1، والنجاح برمز 0.

للتحقق من المانيفست من جهاز آخر، انسخ الرابط ذاته فور توليده، دون إعادة توليده على الجهاز الثاني:

```sh
read -r POC_STREAM_URL
curl --fail --max-time 30 -D /tmp/poc-hls-headers.txt \
  -A 'Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.0 Mobile/15E148 Safari/604.1' \
  -H 'Referer: https://ukrcdn.club/' "$POC_STREAM_URL" \
  -o /tmp/poc-master.m3u8
```

افتح أول رابط جودة في المانيفست، ثم أول مقطع TS في قائمة الجودة باستخدام الترويسات نفسها، مع حل الروابط النسبية مقابل URL القائمة. سجّل وقت توليد الرابط ووقت الطلب والشبكة والاستجابة للمانيفست والجودة والمقطع. كرر على الشبكة الأصلية وعلى 4G قبل `expires`. فشل الشبكة الثانية وحده لا يثبت ربط IP: استبعد انتهاء الصلاحية وقيود الشبكة والجغرافيا، وكرر مقارنة متزامنة برابط جديد.

## بوابة Flutter المتبقية

التطبيق الحالي يقبل في `api_client.dart:mediaUri` مراجع `/api/cinema/media?` و`/api/matches/media?` فقط؛ تمرير CDN URL مباشرة عبر mediaPath سيُرفض بـ `INVALID_MEDIA_REFERENCE`. كما أن `player_page.dart` لا يمرر httpHeaders حاليًا. لم نغير عقد الإنتاج من أجل اختبار غير مكتمل.

في نسخة اختبار محلية على جهاز فعلي، أنشئ controller مؤقتًا هكذا باستخدام الرابط الجديد والترويسات الصادرة من PoC:

```dart
final controller = VideoPlayerController.networkUrl(
  Uri.parse(pocStreamUrl),
  formatHint: VideoFormat.hls,
  httpHeaders: {
    'Referer': 'https://ukrcdn.club/',
    'User-Agent': pocUserAgent,
  },
);
await controller.initialize();
await controller.play();
```

سجّل تقدم currentTime وتحميل المقاطع، ثم seek وتحويل الجودة والاستئناف. تحقق أن ترويسات المانيفست تصل إلى طلبات المقاطع على Android وiOS، وأنها لا تعطي 403. نفذ التجربة على Wi-Fi ثم 4G بالرابط ذاته ضمن الصلاحية. بعد حسم ذلك يمكن تصميم `providers/3isk.mjs` وعقد التشغيل المناسب. إذا ثبت ربط IP فسيتعين تقييم ترحيل المانيفست والمقاطع عبر السيرفر؛ حقن Referer وحده لا يحل ربط IP. الويب المختبر يدعم HLS مباشرًا حاليًا.
