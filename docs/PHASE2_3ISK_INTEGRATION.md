# دمج قصة عشق والتشغيل المباشر

المستودع: `th-505/MATV`. تاريخ التنفيذ والفحص: 2026-10-12 UTC.

## اعتماد تجربة الهاتف

أكد المستخدم تشغيل الرابط الذي ولّدته البيئة على Safari في آيفون عبر 4G، مع الصوت والتقديم والتأخير وتحميل المقاطع دون 403. هذه شهادة المستخدم وليست تجربة نفّذتها البيئة. تدعم النتيجة تشغيل الرابط نفسه من شبكة ثانية دون حقن Referer مخصص، ولذلك اعتمدنا `playback_mode: "direct"` لهذا المزود. ليست النتيجة ضمانًا دائمًا لكل خوادم المصدر أو كل التوكنات. اختبار Flutter على جهاز فعلي يبقى منفصلًا عن اختبارات الوحدات وعن Safari.

الفيديو والمانيفست والمقاطع تُطلب مباشرة من CDN بواسطة العميل. الخادم يجلب صفحات الفهرسة والمشغل وplayback JSON فقط؛ لا يوجد endpoint لنقل فيديو قصة عشق. هذا يلغي باندويث الفيديو على خادم التطبيق، لكنه لا يلغي استهلاك طلبات الاستخراج أو قاعدة البيانات أو تكلفة الاستضافة المحتملة.

## ما تم ربطه

- `server/providers/3isk.mjs`: فهرسة المسلسلات، التصنيف المدبلج، البحث، تفاصيل المواسم والحلقات، جلسة المصدر، استخراج التضمين ثم playback JSON والتوكن.
- تصنيفا `3isk-turkish` و`3isk-dubbed` في API والويب وقائمة الاختيار في تبويب مسلسلات Flutter. البحث العام يجمع نتائج أكوام وقصة عشق؛ تعطل أحدهما لا يمنع نتائج الآخر.
- المراجع `3isk:<base64url path>` ثابتة وقابلة للاسترجاع بعد إعادة تشغيل الخادم، وتحتفظ بها المكتبة بدل روابط CDN المؤقتة. يسمح فكها بمسارات المسلسلات والحلقات المحددة على مصدر قصة عشق فقط.
- المسلسلات تعرض الحلقات بأرقامها المرئية، دون استخدام رقم post الداخلي كرقم الحلقة.
- Flutter يقبل رابط CDN عند إعلان وضع `direct` فقط، ضمن نطاق ukrcdn ومسار HLS المسموح، ويتحقق من صلاحية الرابط. المراجع القديمة لمسارات بروكسي أكوام والمباريات تعمل كما كانت.
- Flutter يعيد الحل عند بدء مشاهدة حلقة قصة عشق، وله محاولة تجديد واحدة عند الفشل، ثم فشل آمن أو المحرك الاحتياطي؛ لا توجد حلقة إعادة محاولات غير محدودة.
- الويب يتحقق من رابط direct وصلاحيته قبل إرساله إلى `Player.html`. لم يُفعّل تنزيل HLS لقصة عشق لأن مسار التنزيل الحالي لا يدعم حفظ مقاطع HLS. تنزيل أكوام والمكتبة الحالية محفوظان.
- لم تتغير ملفات `match-playback.mjs` و`match-production.mjs` و`news-runtime.mjs` أو `providers/akoam.mjs`.

## API

| المسار | الاستخدام |
| --- | --- |
| `/api/v1/categories` | التصنيفات المتاحة |
| `/api/v1/providers` | المزودات ووضع التشغيل وحالة التخزين |
| `/api/v1/category?ref=3isk-turkish&p=1` | مسلسلات قصة عشق |
| `/api/v1/category?ref=3isk-dubbed&p=1` | المسلسلات المدبلجة |
| `/api/v1/search?q=...` | بحث يجمع أكوام وقصة عشق |
| `/api/cinema/details?ref=3isk:...` | تفاصيل المسلسل أو حل رابط الحلقة ضمن عقد التطبيق الحالي |
| `/api/cinema/details?ref=3isk:...&refresh=1` | تجاوز الكاش وتجديد رابط الحلقة |
| `/api/v1/3isk/status` | حالة المزود والتخزين |
| `/api/v1/3isk/search?q=...` | بحث قصة عشق وحده |
| `/api/v1/3isk/category?ref=3isk-turkish&p=1` | فهرسة المصدر وحده |
| `/api/v1/3isk/details?ref=3isk:...` | التفاصيل أو حل الحلقة |
| `/api/v1/3isk/resolve?ref=3isk:...` | حل مرجع الحلقة |

استجابة الحلقة تتضمن `media_url` و`media_path` متساويين، `media_type: "m3u8"`، `playback_mode: "direct"`، `expires_at` من التوكن، `playback_headers: {}`، و`download_available: false`. استجابات الروابط تحمل `Cache-Control: no-store`، ولا تُحفظ روابط التوكن في ملفات الأدلة أو سجل المكتبة.

## Supabase

المشروع الذي حدده المستخدم: `roqccichwszxamdpvhli`، الرابط `https://roqccichwszxamdpvhli.supabase.co`.

طُبّقت المهاجرتان المسجلتان في `supabase/migrations/` فعليًا، وأُنشئت:

- `matv_provider_cache`: مفتاح مركب `(provider, cache_key)`، JSON payload، `expires_at` و`updated_at`. روابط التشغيل المؤقتة تُحفظ داخل payload خاص بالخادم.
- `matv_provider_events`: نجاح أو فشل الاستخراج، مدته ومرجع العمل ووقت العملية. لا تُحفظ IP المستخدم أو التوكنات أو الترويسات أو الأسرار في هذه السجلات.

الجدولان يستخدمان RLS، مع سحب جميع صلاحيات `PUBLIC` و`anon` و`authenticated` ومنح الخادم `service_role` فقط صلاحيات البيانات. لا توجد سياسات وصول للعملاء عمدًا؛ إشعار `RLS Enabled No Policy` معلوماتي ومتوقع هنا. عولج أيضًا تحذير صلاحية RPC للدالة الموجودة `rls_auto_enable`: سُحبت صلاحيات تنفيذها من العملاء مع إبقاء event trigger ومالكه postgres. لم يُعدّل منطق الدالة.

اجتاز اختبار SQL فعلي تحت دور `service_role` إدراج الكاش والسجل ثم قراءة صف غير منتهٍ، داخل transaction أُعيدت بالتراجع بعد الفحص. وأكدت استعلامات الصلاحيات أن العملاء لا يستطيعون قراءة الجدولين. فحص security advisors الأخير لم يرجع تحذيرات WARN، بل إشعاري السياسة المقصودين فقط. فهارس الانتهاء والاحتفاظ جديدة، ولذلك قد تظهر كمعلومات `unused_index` إلى أن يبدأ الاستخدام.

راجع [إشعار RLS بلا سياسة](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) و[توثيق تأمين Data API](https://supabase.com/docs/guides/api/securing-your-api).

### اتصال التخزين من عملية Node

تفعّل الاتصال في هذه البيئة بعد توفير المستخدم مفتاح الخادم. حُفظ في `/workspace/.secrets/matv-server.env` بصلاحية `600` ومجلد خاص بصلاحية `700`، خارج المستودع وجذر خادم الويب المحلي وغير موجود في أي ملف متتبع. اتصال MCP الذي أنشأ الجداول لا يحقن مفتاحه تلقائيًا في Node؛ لذلك استُخدم كاش الذاكرة في الفحص الأول قبل توفير المفتاح.

نجح فحص REST الفعلي من Node: الطلب الأول ولّد الرابط مع `cached: false`، وحفظه في `matv_provider_cache` وسجل عملية `resolved` في `matv_provider_events`. الطلب الثاني أعاد `cached: true`. ثم أُعيد تشغيل Node وأعاد الطلب الرابط نفسه مع `cached: true`، ما يثبت استرجاعه من Supabase بعد زوال كاش الذاكرة. الحالة وقت الفحص: `storage: "supabase"` و`storage_error: null`.

رابط التوكن الحي ينتهي عند `2026-10-13T01:10:00Z`، بينما صف الكاش ينتهي عند `2026-10-13T00:10:00.651Z` التزامًا بحد الخمس ساعات. لا تُنشر قيمة التوكن أو مفتاح الخادم في التقرير. أكد SQL أن الصف صالح ويحمل وضع `direct`.

عند نقل الخادم إلى بيئة جديدة، أضف إلى أسرارها:

```text
SUPABASE_URL=https://roqccichwszxamdpvhli.supabase.co
SUPABASE_SECRET_KEY=<server secret key>
```

يمكن استخدام `SUPABASE_SERVICE_ROLE_KEY` القديم بدل المفتاح الجديد. لا يُستخدم publishable key للخادم، ولا يُرسل المفتاح السري إلى Flutter أو الويب أو GitHub. يوجد `.env.example`، وجميع ملفات `.env` الحقيقية مستبعدة من Git.

أعد تشغيل Node بعد إضافة الأسرار. في هذه البيئة يُستخدم الملف الخاص خارج جذر الويب:

```sh
node --env-file=/workspace/.secrets/matv-server.env server/index-runtime.mjs
```

لإعادة التحقق: افتح `/api/v1/3isk/status`، اطلب حل الحلقة، ثم اطلبها مجددًا بعد إعادة تشغيل الخادم وتحقق من `cached: true` ووجود صف playback في الجدول. `storage: "supabase"` يعني وجود إعدادات الاتصال، وليس وحده دليلًا على نجاح القراءة والكتابة؛ راقب `storage_error` وافحص الصفوف. عند غياب الإعدادات يظهر `storage: "memory"`؛ وعند فشل قاعدة البيانات يستمر الاستخراج المباشر مع إعلان حالة التخزين المتدهورة.

### سياسة الكاش

- الفهرسة: خمس دقائق، البحث: دقيقة، تفاصيل المسلسل: عشر دقائق.
- التشغيل: الأصغر من خمس ساعات أو انتهاء التوكن ناقص 60 ثانية.
- يفحص الكاش المحلي والمحفوظ وقت انتهاء التوكن كل مرة، ولا يستخدم رابط تشغيل منتهيًا أو stale-if-error للفيديو.
- تجديد `refresh=1` يمسح النسخة المحلية والمحفوظة أولًا؛ الفشل لا يعيد رابطًا سبق رفضه.
- الطلبات المتزامنة للمفتاح نفسه تتشارك عملية الاستخراج داخل العملية.
- ينظف المخزن الصفوف المنتهية والسجلات الأقدم من 30 يومًا عند الاستخدام، بحد مرة في الساعة لكل عملية. لا يوجد Cron خارجي في هذه المرحلة، ولذلك يحتاج حذف البيانات أثناء توقف الخادم إلى مهمة تشغيل منفصلة لاحقًا.

## التشغيل والتحقق

```sh
npm ci
npm run check
npm start
```

في البيئة السحابية الحالية مع Node 24 وبروكسي الخروج استخدم `node --use-env-proxy server/index-runtime.mjs` بدل `npm start`، مع إضافة `--env-file=/workspace/.secrets/matv-server.env` لتحميل الأسرار المحلية. يحافظ ذلك على مسار الشبكة والتأكد من TLS.

للواجهة المحلية، شغّل في نافذة أخرى `python -m http.server 8000`. الواجهة على localhost تستخدم API على `http://127.0.0.1:3000`. لبيئة منشورة أخرى اضبط `<meta name="matv-api-base" content="https://your-api.example">` في الصفحة. Flutter يدعم `--dart-define=MATV_API_BASE=https://your-api.example`، مع الإبقاء على عنوانه الافتراضي السابق حتى يُختار عنوان الاستضافة الجديد. يجب أن يكون الخادم قابلًا للوصول من جهاز المستخدم؛ localhost على الهاتف لا يشير إلى هذه البيئة.

الاختبارات التي اجتازت التنفيذ:

- `npm run check` واختبارات المزود والجلسة والمراجع والتوجيه الآمن، والكاش والانتهاء والتجديد وفشل Supabase وعقد HTTP.
- اختبارات content runtime وhome، HTTP، production entry، المباريات، الأخبار، CORS، الفهرسة المتتابعة، فصل التنزيل والمشاهدة وانتهاء مراجع الوسائط.
- `flutter analyze` دون أخطاء، وجميع اختبارات Flutter في وضعي الهاتف وTV، بما فيها الاختبار الجديد للرابط المباشر ورفض الروابط العشوائية والمنتهية ومسار التنزيل الخاطئ.
- اختبار حي عبر `scripts/3isk_browser_smoke.mjs`: قائمة قصة عشق → بطاقة المنظمة → الحلقة 187 → مشغل المشروع الحقيقي. Chromium 154.0.8037.57 تقدم إلى `3.017` ثانية في الفحص الأول وإلى `3.019` ثانية بعد تفعيل Supabase، readyState=4؛ master والجودة 200، وثلاثة مقاطع TS أعادت 206 من CDN مباشرة دون 403.
- الفهرسة الحية أعادت 28 عملًا في الصفحة الأولى و188 حلقة للمنظمة. عُدّل انتهاء التصفح لقصة عشق كي لا يتوقف عند صفحة أقل من 30 عملًا، إذ حجم صفحة المصدر مختلف عن أكوام.

لإعادة اختبار المتصفح مع الخادم والواجهة المحلية قيد التشغيل:

```sh
POC_CHROMIUM_PATH=/usr/bin/chromium node scripts/3isk_browser_smoke.mjs
```

يتطلب Chromium مثبتًا. لا يعطّل الاختبار CORS أو TLS ولا يحقن Referer للبث.

أُنجز دمج المستودع وتفعّل Supabase من عملية الخادم في هذه البيئة. لا يشمل ذلك نشر Render أو GitHub Pages أو إصدار تطبيق للهاتف؛ وإثبات عمل AVPlayer/ExoPlayer داخل التطبيق على هاتف حقيقي يحتاج اختبار جهاز بعد البناء.
