# قصة عشق: Router ومحركا استخراج — 1.0.37 / build 37

يقرأ `selectPlayerIframe` رابط iframe من HTML الـWrapper، ويتحقق من النطاق والمسار ثم يختار المحرك عبر switch. لا يبحث عن رابط ukrcdn أولًا في جميع نصوص الصفحة على حساب iframe الفعلي.

- `server/providers/3isk-playback/ukrcdn.mjs`: طلب صفحة المشغل بـReferer=https://3iskk.xyz/؛ استخراج عنوان البث من JS أو API playback الخاص بالمشغل. ترويسة الفيديو النهائية هي أصل CDN نفسه، مثل https://s5.ukrcdn.xyz/، كما يسمح المتطلب. أثبت طلب حي نجاح هذه الترويسة وكذلك ukrcdn.com (200).
- `server/providers/3isk-playback/miravd.mjs`: طلب صفحة miravd مع عنوان الـWrapper الفعلي كاملًا، وفك جدول Dean Edwards بالأساس 2–62 دون eval، مع دعم المسافات حول الوسائط. ترويسة الفيديو هي https://miravd.com/.
- `contract.mjs`: نطاقات بث محددة، وصلاحية التوكن، وتوحيد الاستجابة. `stream_url` و`headers` هي الحقول الجديدة، وتظل `media_url` و`playback_headers` متوافقة مع العملاء السابقين.

## الاستجابة وواجهة API

`GET /api/v1/3isk/resolve?ref=<3isk-reference>&refresh=1` هو مسار استخراج **خادمي مباشر فقط**. عند النجاح يعيد:

```json
{
  "status": "success",
  "extractor": "miravd",
  "playback_mode": "direct",
  "stream_url": "https://s43.grzcdn.com/hls/.../master.m3u8",
  "headers": {
    "Referer": "https://miravd.com/",
    "User-Agent": "Mozilla/5.0 ..."
  }
}
```

العنوان أعلاه مثال محجوب، وليس رابط بث فعليًا. لا يعيد هذا المسار `resolver_url` أو iframe عند فشل الاستخراج؛ يعيد خطأ JSON بحالة 502. يظل مسار تفاصيل التطبيق القديم قادرًا على الاستخراج الخلفي من العميل عند رفض miravd شبكة الاستضافة، لكي تستمر نسخ الهاتف السابقة. لا يُمرر HTML إلى VideoPlayer ولا تُفتح صفحات متصفح. تغيّر كاش البث إلى v3 مع فصل طلبات الاستخراج الخادمي الصارم عن مسار التوافق.

Flutter يقرأ `stream_url` و`headers` مع قبول الأسماء السابقة. واستخراج miravd الاحتياطي في Dart يدعم Base62 والمسافات أيضًا، ويرسل الـWrapper الذي حدده السيرفر.

## الاختبارات والحدود

نجحت اختبارات Node، وتحليل Flutter، و91 اختبارًا لكل من الموبايل وTV. تشمل الاختبارات التفريع، وترويسة صفحة المشغل، وترويسة الفيديو، وBase62 مع المسافات، ومنع المضيف الخادع، والاستجابة الصارمة التي ترفض إعادة صفحات مشغل كأنها بث مباشر.

اختبار حي على **سيرفر Node داخل هذه البيئة** عبر واجهة HTTP الصارمة:

| المحرك | العمل | API | المانيفست | أول مقطع |
| --- | --- | --- | --- | --- |
| ukrcdn | المنظمة، الحلقة 187 | 200 | 200 | 206 |
| miravd | الرسائل الصفراء، 2026 | 200 | 200 | 206 |

يمكن إعادة الفحص بـ`node --use-env-proxy scripts/3isk_dual_engine_live.mjs`. وللإنتاج يضاف عنوان الخدمة كوسيط. لا يسجل الاختبار التوكن أو عنوان البث الكامل.

**نجاح هذه البيئة لا يعني اكتمال نجاح miravd على Render.** سبق أن أعادت شبكة Frankfurt خطأ 403 رغم إرسال الـWrapper الصحيح. جُربت وظيفة بيانات خلفية محمية على مشروع Supabase الحالي في us-west-1 وus-east-1، مع Referer وreferrerPolicy صريحين؛ أعادت 403 أيضًا. لم تُربط الوظيفة بالـAPI، وأُعيدت حماية gateway JWT إلى true بعد الاختبار. لا تستخدم الوظيفة مفاتيح قاعدة البيانات، ولا تنقل الفيديو. رمز التجربة العشوائي خارج Git؛ يوجد في الكود بصمة SHA-256 فقط، وتتحقق الوظيفة منه قبل أي طلب مصدر.

يلزم اتصال خادم يسمح بجلب miravd لإثبات أن API الإنتاج يعيد stream_url مباشرة للمحركين. لا تُعد المرحلة 1 مكتملة لهذا الشرط حتى ينجح الاختبار على الإنتاج. تجربة الهاتف الاحتياطية السابقة ليست بديلًا عن هذا الإثبات.

لم يتغير كاشط أكوام أو ملفات محركات المباريات والأخبار، ولم تبدأ المرحلة 2.
