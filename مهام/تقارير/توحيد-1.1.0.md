# T-A-TV 1.1.0 / build100 — توحيد التنقل وإصلاح التشغيل

## المنفذ
- تسعة أقسام موحدة بالترتيب في Web وFlutter: الرئيسية، الأفلام، المسلسلات، الأنمي، التركي، البحث، البث، المفضلة، الإعدادات.
- قائمة يمين ثابتة للعرض الواسع وTV/الكمبيوتر، ودرج يمين للجوال. إزالة topbar العام والبحث منه والتنقل السفلي.
- صفحة بحث مستقلة من TMDB وخيار متقدم يثبت مصدر البحث؛ دعم روابط #explore القديمة.
- ألوان وثيم واسم T-A-TV في مصادر الواجهة وملفات branding المولدة للمنصات.
- فلاتر التصفح تستخدم عقد TMDB واحدًا عبر /api/v1/catalog، مع معرفات catalog: ثابتة في Web وFlutter.
- التشغيل: متابعة discovery/start/status، إلغاء عند التنقل، أول نتيجة صالحة أثناء استمرار بقية المصادر، نتيجة نهائية واضحة بدل تجهيز وهمي لا ينتهي، وعدم الرجوع إلى localhost من موقع منشور.
- تحديد الحلقة بمصدرها والموسم والرقم قبل الاستخراج؛ منع الانتقال الصامت إلى مصدر آخر. دعم الموسم المختار في بيانات ومشغل Flutter.
- لا iframe غير آمن، ولا ping وهمي. دعم autoplay الممنوع دون تبديل المصدر الصحيح، ووقت تحميل معقول بدل إسقاطه بعد3ثوانٍ.
- غياب Gemini لا يمنع رابطًا اجتاز فحص الوسائط ومطابقة metadata دقيقة للاسم والسنة والحلقة؛ يبقى التدقيق pending ولا يوصف بأنه تحقق Gemini. اختلاف الهوية أو حكم mismatch لا يُتجاوز.

## دليل الاختبارات المحلية
- Flutter3.47.7: analyze دون ملاحظات، 279 اختبارًا ناجحًا و6 متجاوزة وفق شروطها. اختبارات TV الموجهة 11 ناجحة. فحص إضافي لتفاصيل الموسم ومسار TMDB واختيار المصدر ناجح.
- Node: فحوص المشروع وregressions والبحث وGemini ومسارات التشغيل ناجحة.
- Chromium: قائمة يمين وتفاعل بحث/استكشاف ولوحة مفاتيح دون overflow في390 و1365 و1920px.
- Chromium: التشغيل الفعلي لفيديو H264/AAC بصيغتي MP4 وHLS من fixtures محلية بعد queued/running ثم اختيار S2E4. لا تثبت fixtures توفر فيديو بعينه لدى موقع خارجي.
- Flutter Web بُني محليًا؛ الحزمة المنشورة القديمة app/ تُستبدل فقط بعد اجتياز خط إصدار الحزم الموحدة.

## البناء والنشر
خط الإصدار: .github/workflows/mobile-trial.yml، فرع البناء build/mitv-unified-1.1.0. المنتجات: Android ARM64، TV ARMv7، IPA ARM64 غير موقع، Windows installer/ZIP، macOS DMG، Web ZIP. كل ملف يحمل source-manifest وchecksum ويتحقق script verify_device_artifacts.py من المصدر والإصدار والمعمارية.
لا تُعد أي حزمة مكتملة قبل ظهور artifact ناجح؛ لا يوجد ادعاء بتجربة جهاز فعلي أو توقيع Apple/Windows رسمي. موقع الويب الأساسي يُنشر من main؛ Flutter Web يأتي من نفس مصدر الإصدار بعد نجاح التحقق الجماعي.

## حدود مهمة
المصادر الخارجية قد ترفض الشبكة أو لا تقدم الحلقة أو رابطًا ملائمًا للمتصفح. الرسالة أصبحت صريحة ويمكن اختيار مصدر محدد. اختبار فيلم/حلقة من كل مصدر على كل جهاز ليس ضمن دليل الاختبارات أعلاه.


## إصلاح بناء Apple

فشل البناء على GitHub في `video_player_avfoundation 2.12.3` بسبب تشغيل Xcode 16.4 الافتراضي: `Extra argument isolation in call`. ثُبّت اختيار Xcode 26.3 صراحة في مهمتي iOS وmacOS، وهو مثبت على صورة macos-15. لم تُخفض مكتبات التشغيل ولم تُعطل فحوص الحزم؛ يعاد بناء الإصدار كاملاً من commit واحد ثم ينشر في Releases بعد اجتياز التحقق.
