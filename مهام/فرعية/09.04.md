# 09.04 — حماية مفتاح Gemini وإدارة الحصص

**الحالة:** جزئي — مفاتيح البيئة والاحتياطي والحصص المحلية منفذة ومختبرة.

- حفظ المفتاح في بيئة Render/الخادم فقط؛ لا في GitHub أو JavaScript المتصفح.
- التحقق من وجوده دون طباعة قيمته، وإضافة حدود طلبات وميزانية ومهلات وإعادة محاولات محدودة.
- عند غياب المفتاح أو فشل Gemini: يستمر الفحص التقني ويُسجل «غير مدقق بالذكاء الاصطناعي» دون اعتبار السيرفر موثوقًا تلقائيًا.
- اختبارات منع تسرب المفتاح في API والسجلات والملفات.

## تنفيذ 2026-10-24
**الحالة المحدثة: جزئي — ضوابط الوحدة منفذة ومختبرة؛ الإعداد والتكامل الإنتاجي متبقيان.**

- المفاتيح من `GEMINI_API_KEY` و`GEMINI_API_KEY_BACKUP` في بيئة الخادم فقط. `GEMINI_MODEL` اختياري، وافتراضيه `gemini-2.5-flash` وقابل للتغيير حسب النماذج المتاحة للحساب.
- ينقل المفتاح في `x-goog-api-key` إلى نطاق Google الثابت عبر HTTPS، دون إدخاله في رابط الطلب أو prompt.
- التبديل للاحتياطي فقط عند HTTP 401/403/429؛ أخطاء الشبكة والخادم لا تولد إعادة محاولات متكررة.
- الميزانية الافتراضية 100 استدعاء يوميًا UTC تشمل محاولة الاحتياطي، وحد تزامن 2، ومهلة 8 ثوانٍ، وcache محدود 200 نتيجة بصلاحية يوم. خيارات المصنع تضبطها وفق الاستهلاك.
- هذه الحدود والـcache في ذاكرة عملية واحدة؛ تعدد النسخ أو إعادة التشغيل يحتاج مخزن حصص مركزي قبل الاعتماد على سقف حساب عالمي.
- لا تطبع الوحدة أخطاء HTTP الخام أو المفاتيح، وتنقح الأدلة والردود. status يعرض وجود الإعداد والاستهلاك دون قيم المفاتيح.
- غياب المفتاح أو نفاد الميزانية أو الازدحام ينتج «أدلة غير كافية/غير مدقق» و`eligible:false`، ويظل probe التقني مستقلًا.

### التحقق
`node scripts/media_audit_test.mjs` — نجح محليًا للمفاتيح الأساسية والاحتياطية، التنقيح، الميزانية، timeout حتى إذا تجاهل fetch إشارة abort، والتزامن. لم تضف أسرار إلى المستودع ولم يُنفذ اتصال Gemini حي.

### الإعداد اليدوي
في Render افتح خدمة الخادم ثم Environment وأضف الاسمين السابقين واحفظ التغيير. مفاتيح GitHub Actions تضبط على حدة في Repository Settings → Secrets and variables → Actions. لا تضع المفتاح في HTML أو إعداد عميل أو ملف ملتزم في Git. مراقبة 401/403/429 لا تثبت وحدها انتهاء المفتاح؛ قد تكون صلاحيات أو حصصًا.

### تكامل هذه الدفعة
`server/discovery-audit.mjs` يطبق HEAD probe قبل Gemini ويربط التدقيق في `server/app.mjs` بمسار الاكتشاف والاكتشاف العام للتشغيل. غير المعتمد لا يدخل قائمة التشغيل الافتراضية. اختبار `tests/discovery-audit.test.mjs` يغطي الترتيب والعزل والتنقيح وعدم اختلاق observed. حفظ السجل متصل بالمخزن القائم عند ضبطه؛ اختبار الكتابة الحي والحصة الدائمة عبر النسخ والمفتاح الحي غير مكتملة.
