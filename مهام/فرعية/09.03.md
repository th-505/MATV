# 09.03 — مراجعة السيرفرات باستخدام مفتاح Gemini

**الحالة:** جزئي — الكود والتكامل المحلي منفذان؛ التحقق الحي غير مكتمل.

## الهدف
تحليل نتائج القواشط ومعلومات كل سيرفر وربطها بعنوان العمل والموسم والحلقة. Gemini طبقة تدقيق مساعدة لا بديلًا عن الفحص التقني.

## المدخلات
- معرف المصدر والقاشط والمرجع الداخلي للعمل والحلقة.
- عنوان العمل وسنة الإنتاج وTMDB عند توفره.
- بيانات رابط السيرفر المسموح بمشاركتها بعد حذف الرموز الحساسة.
- أدلة تقنية: نوع الوسائط، حالة HTTP، manifest، بيانات الخادم العامة، ومدة المقطع عند توفرها.

## المخرجات
- قرار: مطابق / مشتبه / غير مطابق / أدلة غير كافية.
- درجة ثقة تفسيرية مع الأسباب والمصدر والوقت، دون ادعاء أنها احتمال معاير.
- منع السيرفر المشتبه أو غير المطابق من العرض الافتراضي حتى مراجعة فنية.
- عدم إرسال مفاتيح وصول أو روابط موقعة أو بيانات مشاهدة شخصية إلى Gemini.

## التنفيذ
1. طبقة probe تقنية سابقة للذكاء الاصطناعي.
2. جمع أدلة محدودة وآمنة، مع مهلات وحصص.
3. استدعاء Gemini من الخادم فقط بمفتاح بيئة؛ استجابة JSON مقيدة ومتحقق منها.
4. حفظ نتيجة التدقيق في قاعدة البيانات بوقت صلاحية وسجل قابل للتتبع.
5. اختبار حالات الفيديو المكرر والروابط التجريبية والمواسم المتداخلة والفشل.

## معيار الإغلاق
اختبار مثبت لعينات متعددة من مصادر مختلفة، مع سجل نتائج وcommit وبدون تسرب أسرار.

## تنفيذ 2026-10-24
**الحالة المحدثة: جزئي — طبقة الخادم منفذة ومختبرة محليًا؛ الربط الإنتاجي والتحقق الحي غير مكتملين.**

- أضيف `server/media-audit.mjs` بدالة `createMediaAuditor().audit()`.
- المدخلات المسموحة: اسم المزود، الهوية المتوقعة والمرصودة (عنوان/سنة/موسم/حلقة)، وملخص probe تقني. لا تُرسل URL أو manifest أو ترويسات أو معرف مستخدم إلى النموذج.
- الرابط أو بصمة الوسيط يستخدمان اختياريًا محليًا لربط cache بالوسيط، ولا يغادران الوحدة.
- فشل probe، غياب دليل الهوية، اختلاف السنة/الموسم/الحلقة، فشل Gemini أو JSON غير صالح لا ينتج اعتمادًا افتراضيًا.
- المخرجات: `decision` و`confidence` و`reasons` و`aiReviewed` و`eligible` ووقت الانتهاء وبصمة تدقيق. الثقة تفسيرية ولا تعني احتمالًا معايرًا.
- القرار `matched` لا يكفي إلا بثقة 0.8 على الأقل، ومع نجاح البوابات التقنية ودليل هوية مرصود. لا يستطيع النموذج إثبات محتوى الفيديو من HTTP أو عنوان الصفحة وحده؛ جودة الدليل مسؤولية مرحلة جمع الأدلة.
- يدعم التخزين عبر callback `persist({evidence,result})` المنقح، مع علامة فشل حفظ غير كاشفة للأسرار؛ التخزين المستمر ليس مفعّلًا بمجرد وجود هذه الوحدة.

### الاختبار
`node scripts/media_audit_test.mjs` — نجح محليًا: بوابة probe، تعارض الحلقة، غياب الأدلة، عدم تسريب المفاتيح والروابط الموقعة وبيانات المستخدم، مفتاح احتياطي، حد يومي، مهلة، تزامن محدود، JSON صارم، cache ونسخ مستقلة للنتائج، وفشل التخزين.

### المتبقي للإغلاق
- التحقق من حفظ التدقيق في Supabase من بيئة الإنتاج؛ الربط البرمجي بعد probe موجود في app.mjs.
- تجربة عينات حية متعددة ومكررة وخاطئة مع مفتاح مضبوط؛ لم يُستخدم مفتاح حي في هذا الاختبار.
- لا يُعد نجاح fixture شهادة بأن المزودين يعملون أو أن الفيديو مطابق فعلًا.

### تكامل هذه الدفعة
`server/discovery-audit.mjs` يطبق HEAD probe قبل Gemini ويربط التدقيق في `server/app.mjs` بمسار الاكتشاف والاكتشاف العام للتشغيل. غير المعتمد لا يدخل قائمة التشغيل الافتراضية. اختبار `tests/discovery-audit.test.mjs` يغطي الترتيب والعزل والتنقيح وعدم اختلاق observed. حفظ السجل المنقح متصل بمخزن Supabase القائم عند ضبطه؛ اختبار الكتابة الحي والحصة الدائمة عبر النسخ واختبار المفتاح الحي ما زالت مفتوحة.
