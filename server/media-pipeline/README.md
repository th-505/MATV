# نجد تي في — المسار الجديد المستقل

هذا مسار جديد من الصفر. لا يستورد القواشط أو المستخرجات أو ناقل الشبكة القديم، ولا يغيّر تشغيل 1.1.7 المنشور. المخطط التنفيذي الكامل في `docs/najd/MEDIA_PIPELINE_PLAN.md`.

## العقود المستهدفة

1. `providers/<site>.mjs`: قاشط واحد مستقل لكل موقع. البحث يُرجع مرجع العمل ورابطه الفعلي؛ قراءة العمل تُرجع هوية المصدر والنسخة والمواسم والحلقات المرصودة؛ قراءة الحلقة تُرجع روابط مستضيفات فعلية مع سياق المصدر. لا يُرجع نجاح تشغيل.
2. `extractors/<host>.mjs`: مستخرج مستقل لكل مستضيف، مسجل بنطاقات دقيقة. يأخذ رابط المشغل المرصود ويُرجع مرشحات MP4/HLS فقط، مع المعلومات اللازمة للقراءة والصلاحية حين تُلاحظ. النطاق المشابه في مسار الرابط لا يثبت هوية المستضيف. المستضيف غير المدعوم يُسجَّل صراحة.
3. `verification/`: فاحص عام للمرشحات، لا يعرف أسماء المواقع أو تقسيم حلقاتها. يُرجع نتيجة عينة الوسائط أو سبب فشل محدد. النجاح التقني لا يُثبت تطابق محتوى الحلقة ولا فك الترميز على جهاز.

`transport/` بنية اتصال للطبقات الثلاث (قراءة GET حاليًا؛ دعم نماذج POST لاحقًا بحسب الموقع)، وليست قاشطًا رابعًا. يثبت عنوان DNS المفحوص للاتصال، ويفحص كل تحويل HTTPS ويحد القراءة والوقت. لا يُستخدم لنقل الفيديو عبر خادم التطبيق إلى المستخدم.

## المنفذ الآن

- ناقل مستقل محمي، وفاحص MP4/HLS وعينة TS/fMP4/AES-128.
- اختبارات سلبية وموجبة مستقلة، ودون تغيير المشغل أو قاعدة بيانات الإنتاج.
- مجلدا providers وextractors يُملآن بعد جرد مستقل واختيار المسار الأول؛ لا يوجد ادعاء بدعم كل المواقع أو المستضيفات الآن.

لا يُفعّل هذا المسار في الإنتاج قبل اكتمال عقود القاشط والمستخرج واختبار المسار من البحث حتى المشغل، ومقارنة النتائج الفعلية. لا يوجد انتقال صامت إلى التنفيذ القديم عند فشل الجديد.
